# YottaFlex Sales Forecasting Data Dictionary

## Overview

This document describes the ten CSV tables generated by the synthetic sales forecasting platform.

**Primary key (PK):** A field that uniquely identifies a record.

**Foreign key (FK):** A field that references the primary key of another table.

**Logical types:** `STRING`, `INTEGER`, `DECIMAL`, `DATE`, and `TIMESTAMP`. CSV files do not enforce database types; these represent the intended data types.

**Currency:** Monetary values are denominated in USD in the clean baseline dataset.

## 1. Territories

**File:** `territories.csv`

**Primary key:** `territory_id`

**Grain:** One record per sales territory.

| Column | Type | Key | Description |
|---|---|---|---|
| `territory_id` | STRING | PK | Unique territory identifier |
| `territory_name` | STRING | | Human-readable territory name |

**Relationships:** One territory can have many sales representatives and accounts.

## 2. Sales Representatives

**File:** `sales_reps.csv`

**Primary key:** `rep_id`

**Grain:** One record per sales representative.

| Column | Type | Key | Description |
|---|---|---|---|
| `rep_id` | STRING | PK | Unique sales representative identifier |
| `rep_name` | STRING | | Representative name |
| `territory_id` | STRING | FK → `territories.territory_id` | Assigned territory |
| `status` | STRING | | Representative employment or activity status |

**Relationships:** A representative can own many opportunities, perform many activities, have multiple quarterly quotas, and receive booking credit.

**Temporal limitation:** Territory assignments are not effective-dated in the current dataset.

## 3. Accounts

**File:** `accounts.csv`

**Primary key:** `account_id`

**Grain:** One record per customer account.

| Column | Type | Key | Description |
|---|---|---|---|
| `account_id` | STRING | PK | Unique customer account identifier |
| `account_name` | STRING | | Synthetic account name |
| `territory_id` | STRING | FK → `territories.territory_id` | Assigned sales territory |
| `industry` | STRING | | Industry classification |

**Relationships:** One account can have many opportunities.

## 4. Pipeline Stages

**File:** `stages.csv`

**Primary key:** `stage_id`

**Grain:** One record per pipeline stage.

| Column | Type | Key | Description |
|---|---|---|---|
| `stage_id` | STRING | PK | Unique stage identifier |
| `stage_name` | STRING | | Stage label |
| `probability` | DECIMAL | | Baseline probability of winning |

**Stage probabilities:**

| Stage | Probability |
|---|---:|
| Prospecting | 0.10 |
| Qualification | 0.25 |
| Proposal | 0.50 |
| Negotiation | 0.80 |
| Closed Won | 1.00 |
| Closed Lost | 0.00 |

**Relationships:** A stage can be referenced by many opportunities, stage-history events, and forecast snapshots.

## 5. Opportunities

**File:** `opportunities.csv`

**Primary key:** `opportunity_id`

**Grain:** One record per sales opportunity.

| Column | Type | Key | Description |
|---|---|---|---|
| `opportunity_id` | STRING | PK | Unique opportunity identifier |
| `account_id` | STRING | FK → `accounts.account_id` | Associated customer account |
| `rep_id` | STRING | FK → `sales_reps.rep_id` | Opportunity owner |
| `stage_id` | STRING | FK → `stages.stage_id` | Initially generated pipeline stage |
| `amount` | DECIMAL | | Opportunity monetary value |
| `currency` | STRING | | Currency code; USD in clean data |
| `product` | STRING | | Product category |
| `created_date` | DATE | | Opportunity creation date |
| `expected_close_date` | DATE | | Expected closing date |
| `status` | STRING | | Outcome status: open, won, or lost |
| `actual_close_date` | DATE, nullable | | Realized closing date for closed opportunities |

**Relationships:** An opportunity can have multiple stage-history events, activities, and forecast snapshot records. The generator creates at most one booking per won opportunity.

**Lifecycle:** Opportunities begin open and may eventually become won or lost. The terminal stage is recorded in `stage_history`.

**Temporal limitation:** Expected close dates are not historically versioned.

## 6. Stage History

**File:** `stage_history.csv`

**Primary key:** `stage_history_id`

**Grain:** One record per opportunity stage transition.

| Column | Type | Key | Description |
|---|---|---|---|
| `stage_history_id` | STRING | PK | Unique stage-history event identifier |
| `opportunity_id` | STRING | FK → `opportunities.opportunity_id` | Opportunity whose stage changed |
| `stage_id` | STRING | FK → `stages.stage_id` | Stage entered at this event |
| `changed_at` | TIMESTAMP | | Effective timestamp of the stage change |

**Relationships:** One opportunity can have multiple stage-history records.

**Temporal rule:** For a given snapshot date, only stage-history events effective on or before that date may be used.

**Ordering:** Events are ordered by `changed_at` and, when necessary, their unique event identifier.

## 7. Activities

**File:** `activities.csv`

**Primary key:** `activity_id`

**Grain:** One recorded sales activity.

| Column | Type | Key | Description |
|---|---|---|---|
| `activity_id` | STRING | PK | Unique activity identifier |
| `opportunity_id` | STRING | FK → `opportunities.opportunity_id` | Associated opportunity |
| `rep_id` | STRING | FK → `sales_reps.rep_id` | Representative performing the activity |
| `activity_type` | STRING | | Type of sales interaction |
| `activity_date` | DATE | | Date the activity occurred |
| `duration_minutes` | INTEGER | | Activity duration in minutes |
| `status` | STRING | | Activity completion status |

**Relationships:** Activities associate representatives with opportunities.

**Temporal rule:** Activity features in historical forecasts must exclude events after the snapshot date.

## 8. Quotas

**File:** `quotas.csv`

**Primary key:** `quota_id`

**Grain:** One representative's quota for one reporting quarter.

| Column | Type | Key | Description |
|---|---|---|---|
| `quota_id` | STRING | PK | Unique quota identifier |
| `rep_id` | STRING | FK → `sales_reps.rep_id` | Representative assigned the quota |
| `quarter` | STRING | | Reporting quarter, e.g. `2026Q1` |
| `quota_amount` | DECIMAL | | Quarterly quota amount |
| `currency` | STRING | | Quota currency |

**Business key:** `(rep_id, quarter)` should be unique.

**Coverage:** Eight quarters from 2025 Q1 through 2026 Q4.

## 9. Historical Bookings

**File:** `historical_bookings.csv`

**Primary key:** `booking_id`

**Grain:** One realized booking from a won opportunity.

| Column | Type | Key | Description |
|---|---|---|---|
| `booking_id` | STRING | PK | Unique booking identifier |
| `opportunity_id` | STRING | FK → `opportunities.opportunity_id` | Opportunity producing the booking |
| `rep_id` | STRING | FK → `sales_reps.rep_id` | Credited representative |
| `booking_date` | DATE | | Date the booking was recognized |
| `booking_amount` | DECIMAL | | Realized booking amount |
| `currency` | STRING | | Booking currency |

**Business rules:** Bookings must reference won opportunities, have positive amounts, and match the realized close date in the current generator.

**Cardinality:** At most one booking per won opportunity in the current implementation.

## 10. Forecast Snapshots

**File:** `forecast_snapshots.csv`

**Primary key:** `forecast_id`

**Grain:** One opportunity forecasted at one historical snapshot date.

| Column | Type | Key | Description |
|---|---|---|---|
| `forecast_id` | STRING | PK | Unique forecast record identifier |
| `snapshot_date` | DATE | | Historical forecast observation date |
| `quarter` | STRING | | Reporting quarter |
| `opportunity_id` | STRING | FK → `opportunities.opportunity_id` | Forecasted opportunity |
| `rep_id` | STRING | FK → `sales_reps.rep_id` | Opportunity owner |
| `stage_id` | STRING | FK → `stages.stage_id` | Stage known at the snapshot date |
| `deal_age_days` | INTEGER | | Days between opportunity creation and snapshot |
| `activity_count` | INTEGER | | Count of activities known at snapshot |
| `opportunity_amount` | DECIMAL | | Opportunity amount used in the forecast |
| `win_probability` | DECIMAL | | Assigned stage-based win probability |
| `forecast_amount` | DECIMAL | | Probability-weighted opportunity amount |
| `currency` | STRING | | Forecast currency |

**Business key:** `(snapshot_date, opportunity_id)` must be unique.

**Forecast arithmetic:**

`forecast_amount = opportunity_amount × win_probability`

Values are rounded to two decimal places.

**Temporal rule:** Forecast snapshots must not use future stage changes or activities.

**Current modeling limitation:** Deal age and activity count are stored as explanatory features but do not yet modify the stage-based win probability.

## Referential Integrity

The platform checks 15 foreign-key relationships among the ten tables.

Primary keys must be present and unique. Foreign keys must reference valid parent records.

Additional business-rule validation checks booking amounts, close dates, terminal stages, and forecast arithmetic.

## Data Quality and Ground Truth

The anomaly injector creates corrupted copies of the clean CSVs in `data/anomalies/`.

Five anomaly classes are supported:

1. Close date before creation
2. Mixed currency
3. Stage probability mismatch
4. Duplicate opportunity in a snapshot
5. Future-stage leakage

The separate `data/ground_truth.csv` file records the anomaly type, table, record ID, and description. It is used for validation and must not be included in forecasting features.

## Reproducibility

The generator uses seed `20261022`.

The `data/manifest.json` file records the row count and SHA-256 checksum of every clean CSV.

Repeated full-scale generation with the same seed produced byte-identical CSV outputs across all ten tables.
